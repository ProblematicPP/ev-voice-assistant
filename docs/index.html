An EV voice assistant that checks the battery before it says yes

Most in-car assistants turn speech into commands. Volt routes every navigation, charging and climate request through a battery-intelligence core first: trained models for battery health and personalized range, plus a guard that blocks anything the car can't safely do.

What happened behind that first answer

  1. Speech transcribed locally by Whisper.
  2. A local LLM (Qwen 3.5 4B via Ollama) picks the tool check_range_to("Mysore"). It never invents numbers.
  3. The range model predicts Wh/km for every road segment under today's heat, AC, driving style and battery age.
  4. The battery guard compares predicted arrival charge with a 10% reserve: fail.
  5. The planner searches charger combinations and picks the fastest plan that keeps every leg above the floor.
  6. The LLM phrases the reply using only those facts; Piper speaks it.

How a request flows

The language model chooses what to do. Deterministic code backed by the trained models decides whether it can be done. If the LLM is offline, a rule-based parser takes its place, so the assistant still works.

What it can do

Context-aware commands

Destinations are range-checked before navigation starts.

"Take me to the nearest McD"

Range questions in plain language

Answers against the actual route, today's conditions and battery age.

"Will I make it to Mysore without stopping?"

Automatic route and charger choice

Dijkstra over a charger graph picks the fastest feasible plan and charges only as much as the next stretch needs.

Mid-drive re-planning

Add a detour while driving; the stop that minimises the detour is chosen and charging is re-planned from where the car is.

"Also stop at a McDonald's on the way"

Proactive nudges

Unprompted alerts with one-tap answers when the state changes.

"18% left, 56 km from home. Route via a charger?"

Range-drop explanation

Exact Shapley values over weather, AC, driving style, load and battery ageing, in kilometres.

"Why is my range lower than usual?"

Companion app

Personalized SOH and range, charging-habit coaching, cost per km against petrol, and an SOH-driven resale estimate with a two-year habit projection.

Assisted driving and pre-cooling stubs

They log what they would do (show the left turn camera, pre-cool on plug power) without touching hardware. Pre-cooling is still guard-checked.

The battery-intelligence core

No real EV telemetry was available, so all training data is synthetic, generated to resemble public datasets (NASA PCoE and CALCE ageing curves) and plausible vehicle physics. Both models are small PyTorch MLPs.

Predicting Wh/km rather than range directly is what makes range personalized: at 34 °C the same 46% charge is about 125 km with the AC off and 88 km with it on, and the model can say exactly how much each factor costs.

Run it locally

Windows, Python 3.12, Node 18+ and Ollama. An NVIDIA GPU is used automatically for speech recognition and the LLM when available. Full instructions are in the README.

cd backend
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
uv pip install --python .venv\Scripts\python.exe torch --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m data_gen.generate_all
.venv\Scripts\python.exe -m training.train_soh
.venv\Scripts\python.exe -m training.train_range
ollama pull qwen3.5:4b
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000

cd ..\frontend
npm install
npm run dev        # open http://localhost:5173

Limitations

  • All battery, trip and charging data is synthetic; model accuracy figures describe fit to that data, not real vehicles.
  • The road network is a hand-built graph of Bengaluru, Mysuru, Tumakuru and Kolar with approximate coordinates and fictional chargers.
  • Assisted driving and pre-cooling are logging stubs for a future hardware phase.
  • Single vehicle, single owner. Fleet features are out of scope.
